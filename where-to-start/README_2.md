## Шаг 1. Создание аккаунта и безопасное хранение данных (KeePassXC)

1. Зарегистрируйтесь на [GitHub](https://github.com/).
2. Скачайте и установите автономный менеджер паролей **KeePassXC** (создайте базу `.kdbx` с шифрованием **AES-256**).
3. **Включите 2FA (Двухфакторную аутентификацию):**
   * Перейдите в `Settings` $\rightarrow$ `Password and authentication`.
   * Настройте вход через приложение-аутентификатор (Google Authenticator, Aegis и др.).
   * Скачайте 16 одноразовых **Recovery Codes** (кодов восстановления).
   * Скопируйте коды и вставьте их в поле *Notes (Заметки)* внутри записи GitHub в KeePassXC.
   * Удалите исходный `.txt` файл с кодами из папки «Загрузки» на ПК.


## Шаг 2. Настройка приватности Email и защиты от спама

Чтобы ваша личная почта не индексировалась поисковиками и не светилась в публичных коммитах:

1. Перейдите в **Settings $\rightarrow$ Emails** на GitHub.
2. Включите опции:
   * ✅ **`Keep my email addresses private`**
   * ✅ **`Block command line pushes that expose my email`**
3. На странице появится ваш сгенерированный анонимный адрес (например: `Вставить свой адрес`).
4. Откройте **Терминал** (Git Bash / PowerShell) и свяжите анонимный email с локальным Git:

```bash
# Установка имени разработчика
git config --global user.name "Создать свое имя"

# Установка анонимного email
git config --global user.email "Вставить свой адрес"

# Проверка установленных настроек
git config --global --list
```

## 🔐 Шаг 3. Генерация и настройка SSH-ключа

SSH позволяет подключаться к GitHub без повторного ввода пароля при каждой отправке кода.

### 1. Генерация ключа

Открой терминал и выполни команду:

```bash
ssh-keygen -t ed25519 -C "ваша_почта@gmail.com"
```

> 💡 **Совет:** нажимай `Enter`, чтобы использовать стандартный путь сохранения ключа. При необходимости задай парольную фразу для дополнительной защиты.

### 2. Запуск SSH-агента

Запусти агент и добавь приватный ключ:

```bash
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
```

### 3. Добавление ключа на GitHub

**🪟 Windows PowerShell**

```powershell
Get-Content ~/.ssh/id_ed25519.pub | Set-Clipboard
```

**🐧 Linux**

```bash
cat ~/.ssh/id_ed25519.pub
```

**🍎 macOS**

```bash
pbcopy < ~/.ssh/id_ed25519.pub
```

Затем:

1. Открой [GitHub SSH Settings](https://github.com/settings/keys).
2. Нажми **New SSH key**.
3. Введи название, например `Home-PC`.
4. Вставь публичный ключ и нажми **Add SSH key**.

> ⚠️ Никогда не публикуй приватный ключ `id_ed25519`. На GitHub добавляется только публичный ключ `id_ed25519.pub`.

### 4. Проверка подключения

```bash
ssh -T git@github.com
```

Успешный результат:

```text
Hi username! You've successfully authenticated, but GitHub does not provide shell access.
```

✅ **Готово! SSH-аутентификация настроена.**

## 🛡️ Шаг 4. Защита от утечек секретов

API-ключи, токены и пароли не должны попадать в публичные репозитории.

### Включение Push Protection

1. Открой [GitHub Security Settings](https://github.com/settings/security_analysis).
2. Найди настройку **Push protection for yourself**, если она доступна для твоего аккаунта.
3. Включи защиту.

GitHub может блокировать отправку коммитов, содержащих обнаруженные секреты.

> 🔒 **Важно:** Push Protection — дополнительный уровень безопасности, а не замена осторожности. Не добавляй токены, пароли и приватные ключи в код.

## 👤 Шаг 5. Настройка профиля GitHub

### 1. Ветка по умолчанию

В настройках репозитория или аккаунта установи `main` в качестве имени основной ветки по умолчанию, если это необходимо.

### 2. Оформление профиля

Открой [GitHub Profile Settings](https://github.com/settings/profile).

| Поле | Пример |
|---|---|
| **Name** | Твоё имя или ник |
| **Bio** | `Python Developer in training \| Learning Backend Development` |
| **Public Email** | Можно оставить пустым |

### 3. Настройка уведомлений

Открой [Notification Settings](https://github.com/settings/notifications) и отключи **Automatically watch repositories**, если не хочешь получать лишние уведомления.

## 📦 Шаг 6. Публикация проекта на GitHub

Разберём полный цикл: от создания папки проекта до отправки кода в удалённый репозиторий.

### 1. Создание папки проекта

```bash
cd path/to/your/projects
mkdir my-python-project
cd my-python-project
```

### 2. Инициализация Git

```bash
# Инициализация репозитория
git init

# Установка основной ветки
git branch -M main

# Создание README
echo "# My Python Project" > README.md

# Проверка состояния
git status

# Добавление файлов
git add .

# Первый коммит
git commit -m "Initial commit: create project structure"
```

> 💡 Если Git ещё не настроен, укажи имя и email:

```bash
git config --global user.name "Your Name"
git config --global user.email "your_email@example.com"
```

### 3. Создание удалённого репозитория

1. Открой [GitHub](https://github.com/new).
2. Создай новый репозиторий.
3. Если локально уже создан `README.md`, не добавляй второй README при создании удалённого репозитория.
4. Скопируй SSH-адрес репозитория.

Пример адреса:

```text
git@github.com:username/repository-name.git
```

### 4. Подключение и отправка кода

```bash
# Привязка удалённого репозитория
git remote add origin git@github.com:username/repository-name.git

# Отправка проекта на GitHub
git push -u origin main
```

🎉 **Поздравляю! Твой проект опубликован на GitHub.**

## ⚡ Шпаргалка по командам Git

| Команда | Назначение |
|---|---|
| `git status` | Проверить состояние файлов |
| `git add .` | Добавить изменения в индекс |
| `git add script.py` | Добавить конкретный файл |
| `git commit -m "message"` | Создать коммит |
| `git push` | Отправить коммиты на GitHub |
| `git pull` | Получить изменения с GitHub |
| `git log --oneline` | Просмотреть историю коммитов |
| `git branch` | Посмотреть локальные ветки |
| `git diff` | Просмотреть изменения |
| `git remote -v` | Посмотреть удалённые репозитории |

### 🔄 Типичный рабочий процесс

```bash
# 1. Проверить изменения
git status

# 2. Добавить файлы
git add .

# 3. Зафиксировать изменения
git commit -m "feat: add user authorization logic"

# 4. Отправить коммиты на GitHub
git push
```
