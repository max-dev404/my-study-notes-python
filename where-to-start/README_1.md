# Flake8 и Ruff в Python

Практическое руководство: назначение, сравнение, выбор и установка.

> **Краткий вывод:** для большинства новых Python-проектов разумно начать с **Ruff**. Он объединяет линтинг и форматирование, быстро работает и обычно требует меньше отдельных инструментов. **Flake8** остаётся полезным в существующих проектах, особенно если они зависят от специфичных плагинов.

## 1. Что это

### Что такое линтер

**Линтер** — это инструмент статического анализа. Он проверяет исходный код без запуска самой программы и сообщает о подозрительных конструкциях, потенциальных ошибках и нарушениях выбранных правил.

Линтер не гарантирует, что программа работает правильно, и не заменяет тесты, проверку типов или ревью кода.

### Flake8

**Flake8** — классический линтер Python. Он объединяет проверки нескольких инструментов, в том числе:

- **PyFlakes** — выявление некоторых потенциальных ошибок, например неиспользуемых импортов и неопределённых имён.
- **pycodestyle** — проверка стиля кода, связанного с PEP 8.
- **McCabe** — измерение цикломатической сложности кода.

Дополнительные проверки можно подключать через плагины.

### Ruff

**Ruff** — быстрый линтер и форматтер Python, реализованный на Rust. Он содержит множество правил, покрывающих типичные задачи Flake8 и популярных плагинов. Ruff умеет автоматически исправлять часть нарушений и отдельно форматировать код. Настройки удобно хранить в `pyproject.toml`.

## 2. Зачем это нужно и как работает

Линтер помогает:

- находить неиспользуемые импорты и другие подозрительные конструкции;
- замечать некоторые распространённые ошибки до запуска программы;
- поддерживать единый стиль в команде;
- автоматизировать проверки в редакторе и CI;
- сокращать количество замечаний на ревью.

### Пример

```python
import os

def calculate_total(price, tax):
    return price + tax
```

В этом примере `os` не используется. Линтер может сообщить о неиспользуемом импорте.

### Линтер, форматтер, проверка типов и тесты — разные вещи

| Категория | Что делает | Примеры |
|---|---|---|
| Линтер | Ищет подозрительный код и нарушения правил | Ruff check, Flake8 |
| Форматтер | Приводит оформление к единому виду | Ruff format, Black |
| Проверка типов | Проверяет согласованность типов и аннотаций | Pyright, mypy, ty |
| Тесты | Проверяют поведение программы | pytest |

Форматтер исправляет оформление — пробелы, переносы строк, расположение выражений. Он не гарантирует правильность логики. Проверка типов и тесты решают другие задачи.

## 3. Какими инструментами пользуются

Типичный набор инструментов для Python-проекта:

- **Ruff** — линтинг, автоматическое исправление части нарушений и форматирование.
- **Pyright или mypy** — статическая проверка типов, если проект использует аннотации типов.
- **pytest** — автоматические тесты.
- **pre-commit** — запуск выбранных проверок перед коммитом.
- **CI** (например, GitHub Actions) — проверка кода на сервере при отправке изменений.
- **Bandit** — дополнительный поиск некоторых потенциально опасных конструкций в Python-коде.

Black и isort не обязательно устанавливать отдельно, если проект использует `ruff format` и правила Ruff для импортов. Pylint можно добавить для дополнительных проверок, если есть конкретная потребность.

## 4. Сравнение: Flake8 и Ruff

| Критерий | Flake8 | Ruff |
|---|---|---|
| Основное назначение | Линтер | Линтер и форматтер |
| Скорость | Обычно ниже | Обычно значительно выше; результат зависит от проекта |
| Реализация | Python и Python-пакеты | Rust |
| Проверки ошибок и стиля | Да | Да, через выбранные правила |
| Сортировка импортов | Через плагины или отдельные инструменты | Правила группы `I` |
| Автоматическое исправление | Зависит от плагинов и дополнительных инструментов | Поддерживается для многих правил |
| Форматирование | Не входит в сам Flake8 | Есть отдельная команда `ruff format` |
| Расширение | Большая экосистема Python-плагинов | Много встроенных правил, но не каждому плагину Flake8 есть точная замена |
| Конфигурация | Зависит от формата конфигурации и плагинов | Удобно хранить в `pyproject.toml` |
| Когда выбирать | Существующий проект со специфичными плагинами | Большинство новых проектов |

### Другие полезные инструменты

| Инструмент | Назначение | Когда рассмотреть |
|---|---|---|
| **Pylint** | Дополнительные проверки кода и эвристики | Когда нужны проверки сверх Ruff |
| **Black** | Форматирование | Если проект уже стандартизирован на Black |
| **isort** | Сортировка импортов | Если не используются возможности Ruff |
| **Pyright / mypy / ty** | Проверка типов | Для типизированного кода |
| **Bandit** | Некоторые проверки безопасности | Как дополнительный уровень, не как полный аудит |
| **pytest** | Тестирование поведения | Практически в любом Python-проекте |

### Рекомендация

Для нового проекта начните с **Ruff + pytest**. Если используете аннотации типов, добавьте **Pyright** или **mypy**. Pylint и отдельные средства безопасности добавляйте при наличии конкретной потребности.

Не включайте все возможные правила сразу: начните с полезного базового набора и расширяйте его постепенно.

## 5. Установка и практическая настройка

### Установка Ruff

В активном Python-окружении через `pip`:

```bash
python -m pip install ruff
```

Если проект управляется `uv`, добавьте Ruff как зависимость разработки:

```bash
uv add --dev ruff
```

Выберите один подход, подходящий вашему проекту. Для командной работы полезно закреплять инструменты в зависимостях проекта и lock-файле, если используемый менеджер его поддерживает.

### Пример `pyproject.toml`

Добавьте в `pyproject.toml`:

```toml
[tool.ruff]
line-length = 88
target-version = "py312"

[tool.ruff.lint]
select = [
    "E",     # Стиль pycodestyle
    "F",     # Pyflakes: потенциальные ошибки
    "W",     # Предупреждения pycodestyle
    "I",     # Сортировка импортов
    "B",     # Распространённые ошибки
    "UP",    # Современный синтаксис Python
    "SIM",   # Упрощение кода
    "RUF",   # Специфичные правила Ruff
]
```

**Важно:**

- `line-length = 88` задаёт целевую длину строки для форматирования.
- `target-version = "py312"` уместен, если проект рассчитан на Python 3.12 или использует совместимую с ним политику. Для проекта, поддерживающего более старую версию Python, укажите соответствующую версию.
- `select` определяет группы включённых правил.
- Можно включить правила безопасности группы `S`, но они способны выдавать предупреждения на допустимые сценарии и не заменяют аудит безопасности.

### Основные команды Ruff

Проверить код:

```bash
ruff check .
```

Автоматически исправить поддерживаемые нарушения:

```bash
ruff check --fix .
```

Показать возможные исправления без изменения файлов:

```bash
ruff check --diff .
```

Отформатировать код:

```bash
ruff format .
```

Проверить форматирование, не изменяя файлы:

```bash
ruff format --check .
```

### Рекомендуемый порядок работы

1. Выполните `ruff check .` и изучите найденные проблемы.
2. Выполните `ruff check --fix .`, чтобы исправить поддерживаемые нарушения.
3. Выполните `ruff format .`, чтобы привести код к единому стилю.
4. Повторно выполните `ruff check .` и изучите оставшиеся сообщения.
5. Запустите тесты: `pytest`.
6. При необходимости запустите проверку типов: `pyright` или `mypy`.
7. Добавьте проверки в CI, чтобы нарушения обнаруживались до слияния изменений.

### Проверки в CI

Например:

```bash
ruff check .
ruff format --check .
pytest
```

Команда `ruff format --check .` проверяет форматирование, но не изменяет файлы. Добавьте команду проверки типов, если она используется в проекте.

## 6. Переход с Flake8 на Ruff

Если проект уже использует Flake8, переходите постепенно:

1. Посмотрите на текущие правила, плагины, исключения и директивы `noqa`.
2. Подберите соответствующие правила Ruff и перенесите настройки в `pyproject.toml`.
3. Сравните результаты обоих инструментов на кодовой базе.
4. Проверьте сторонние плагины: у Ruff нет гарантированной замены каждому плагину Flake8.
5. Запустите тесты и включите Ruff в CI.
6. Удалите Flake8 только после проверки, что нужные проверки не потеряны.

Ruff заменяет Flake8 во многих типичных проектах, но совместимость не абсолютна.

---

## 7. Итог

- **Для большинства новых проектов — Ruff.** Он быстрый, поддерживает автоматические исправления и включает форматтер.
- **Flake8** стоит сохранить, если проект зависит от специфичных плагинов или его текущая конфигурация хорошо работает.
- **Pyright или mypy** нужны для статической проверки типов.
- **pytest** проверяет поведение программы.
- **CI и, при необходимости, pre-commit** помогают выполнять проверки систематически.
